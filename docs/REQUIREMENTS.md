# 需求与验收标准

## 首版范围（v0.1.0）

IMAP-Notify 是一个面向个人、小规模多邮箱使用的 Rust 常驻服务。通过 IMAP IDLE 感知新邮件，向一个全局 Bark 地址发送包含账户、发件人、主题和图标的通知。支持 Linux 与 macOS，Linux 提供 systemd 部署。

| 编号 | 需求 | 验收方式 |
| --- | --- | --- |
| R01 | 多账户独立监听，单账户连接失败不阻断其他账户 | 每账户线程；人工双账户故障测试 |
| R02 | 默认 IMAPS，非 993 端口必须成功 STARTTLS；校验证书 | 底层库加密模式审查；真实服务器验证 |
| R03 | 仅通知首次连接之后的新 UID，保留未读状态 | 模拟 IMAP 检查旧 UID 过滤、`BODY.PEEK` 命令 |
| R04 | 同一进程重连保留进度，补查断线窗口；UIDVALIDITY 改变则重建基线 | 模拟重连与 UIDVALIDITY 测试 |
| R05 | 每封邮件处理后推进进度；后续 FETCH 失败不重发已处理邮件 | 批次部分失败回归测试 |
| R06 | IDLE 超时回到业务层检查，支持 60–1740 秒；断线退避 5–300 秒，成功 IDLE 后重置 | 模拟超时与退避重置测试 |
| R07 | 中文 MIME 主题、发件人解码；缺失字段回退，长文本按字符截断 | 邮件解析及通知 payload 单测 |
| R08 | 图标优先级：账户 > 全局 > 发件人域名；支持分组、声音、级别和点击链接 | payload 与不可信域名测试 |
| R09 | Bark HTTP 成功且 JSON 整数 code=200 才算成功；失败最多重试一次 | 本地 HTTP 错误、无效 JSON、业务失败和恢复测试 |
| R10 | 单一 Bark URL；错误中隐藏设备 Key 和密码命令，默认日志不含邮件内容 | 错误脱敏、配置 Debug 和 CLI 回归测试 |
| R11 | TOML 严格校验；密码或可信密码命令；`--check` 离线且不执行命令 | 配置、CLI、空输出与命令失败测试 |
| R12 | `--test-bark` 无需邮箱账户，不连接 IMAP、不执行密码命令 | 配置模式与本地 HTTP 测试 |
| R13 | 非 root systemd 服务，限制配置文件读取权限 | unit 审查与目标 Linux 手动验收 |
| R14 | GitHub CI、四种原生二进制、校验清单、版本标签自动发布 | GitHub Actions 与 Release 页面验收 |

## 明确的产品语义

1. 启动和进程重启均跳过历史邮件；内存进度只跨网络重连，不跨进程生命周期。
2. 收到邮件不等于保证 iPhone 显示通知。推送重试后失败会丢弃，超时重试也可能重复。
3. UIDVALIDITY 变化代表 UID 空间重建，旧进度不得沿用；首次基线之后仍存在的邮件才有机会被抓取。
4. 邮件头已被删除时无法推送；一次 FETCH 的其他 UID 非请求响应不能当作目标邮件通知。
5. 保留同步 IMAP 库和每账户线程的架构，不引入与当前需求不相称的异步迁移。
6. 图标与邮件通知内容会触达配置中的外部服务；固定图标可替代自动域名图标。

## 不在首版范围

- 多 Bark 目标、OAuth2/XOAUTH2、正文/附件读取、Web 管理后台。
- 跨进程持久化进度、严格一次送达、无限重试队列。
- 多文件夹动态发现、配置热加载、Windows 发布包。
- 邮箱提供方账号申请、真实设备凭据管理和无人值守端到端验收。

## 发布后的人工验收

- 真实邮箱首次启动不推历史邮件，中文新邮件可在 iPhone 展示，未读状态保持。
- 两账户同时监听；让其中一个认证失败，另一账户仍正常推送。
- 断网期间投递邮件，恢复连接后补发；重启进程后不补发停机邮件。
- 检查固定图标、自动图标、声音和点击链接。
- 在 Linux 使用专用账户启动服务，验证配置权限、重启与日志。

没有提供真实邮箱凭据及 iPhone，本轮不将这些手工项标记为已通过。
